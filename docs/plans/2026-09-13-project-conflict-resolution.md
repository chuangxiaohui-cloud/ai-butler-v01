# 项目冲突重新校验与事务级执行

## 目标

- 只接受 E396 append-only 裁决事件作为执行依据，并校验其事务身份和选择。
- 执行前复核全部事务路径；任何存在状态或摘要变化都零写入并返回新的确认契约。
- `keep_external` 保留冲突文件、提交其余文件；`use_transaction` 提交整批；`cancel_all` 零写入。
- 写入前基于当前状态重新准备恢复快照，确保失败回滚恢复到用户确认时的外部版本。

## 非目标

- 本轮不把内存事务持久化为可由 gateway 独立恢复的任务。
- 不接 project-writer 多文件自然语言入口或 EDA 写操作。
- 不自动选择、不自动重试、不合并文件正文。

## 验收标准

- 缺失、非法或错事务裁决证据拒绝执行。
- 三种选择语义稳定；取消与状态变化均零写入。
- 外部状态再次变化返回 `reconfirmation_required` 和新冲突契约。
- 提交失败时从新快照恢复确认时版本，既有事务/裁决测试保持通过。

## 执行过程

### 改动

- 新增事务级冲突解析器，只从 decision log 查找已落盘的 selectedChoice/refId 事件，并核对 pending、事务身份、完整冲突契约与选择结果。
- 执行前复核全部事务路径；确认后再变化时返回 `reconfirmation_required` 和新的三选一契约，目标零写入。
- `cancel_all` 保留全部当前状态；`keep_external` 排除冲突路径后提交其余文件；`use_transaction` 提交整批。
- 两个写入型选择均基于当前状态重新 prepare 新事务；新快照基线还会与用户确认状态比对，再由既有 commit 冲突门做最后一次检查。

### 遇到的问题

- 直接复用旧事务快照会在提交失败时把用户已确认的外部修改回滚掉；改为重新准备恢复快照，失败恢复到确认时版本。
- “复核成功→创建新快照”之间仍存在文件系统竞态；新增新快照基线比对，随后复用 commit 的最终摘要检查，任一阶段变化都重新阻断。
- gateway 当前没有安全持有内存事务正文的事务仓库；本轮只落核心执行契约，待 project-writer 多文件入口接入时由同一进程显式调用，不从 decision log 反推文件正文。

## 结果

- `npm run build`：通过。
- 定向测试 30/30 通过，其中 E397 新增 6 个用例，覆盖缺失/错事务证据、取消、重新确认、保留外部、使用事务和失败回滚。
- 已验证 `use_transaction` 中断后恢复到确认时外部版本，而非 E393 原始旧版本。
- 未运行 E2E、全量 bench 或真实 EDA 写操作；未提交。
