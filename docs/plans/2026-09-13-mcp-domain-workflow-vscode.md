# MCP 领域工作流规格补强与 VS Code 子 Agent 占位

> 日期：2026-09-13 · 分支：v0.2b · 状态：已完成

## 目标

- 把 §4.1.2 的 MCP 子 Agent 从软件清单补强为可实施的三层架构、领域入口、动态工作流、结构化产物与双门验收规格。
- 把 VS Code 纳入嵌入式开发常用软件、工程栏角色面板和子 Agent 注册表，保持未接入时诚实显示占位。
- 登记用户提供的 MCU 工作流展示图，只借鉴职责拆分与工作流表达，不照搬 Skill 数量、名称或底座。

## 非目标

- 不安装、不启动、不控制真实 VS Code，不假定已存在可用 VS Code MCP server。
- 不实现自主 LLM 规划、多 Agent DAG 执行器或新的写权限。
- 不复制外部展示图中的版本号、十三个固定 Skill 或“自动完成”的能力宣称。

## 验收标准

- 需求正文明确 Skill、子 Agent、MCP Tool 三层边界以及领域入口、动态编排、产物交接、质量门和人工门。
- VS Code 同时出现在常用软件、工程栏子 Agent 列表与代码注册表，默认 `available=false`、命令为空、工具前缀独立。
- 外部设计借鉴、附录 A E400、目录文档和当日交接记录一致。
- TypeScript build、MCP registry 定向测试、`git diff --check` 与 `doc-lint` 完成；不运行 E2E/bench。

## 执行过程

### 改动

- §4.1.2 新增三层边界、统一领域入口、动态工作流节点、结构化产物交接、质量门和人工门；§11.1 失败矩阵回指该工作流。
- §3.3 与工程栏角色面板增加 VS Code，并明确它是跨领域编辑器，单独安装不能作为嵌入式职业推断依据。
- `src/mcp/registry.ts` 增加 `vscode` 编码类占位，独立 `vscode.` 工具前缀、默认不可用且无启动命令；gateway 目录测试确认 UI 数据源可见且状态诚实。
- 外部展示图的借鉴范围登记到 `docs/borrowed-designs.md`；需求附录 A 登记 E400，目录文档、验收差量和当日交接同步。

### 遇到的问题

- E399 交接曾预留 E400 给冲突执行闭环；owner 插入本轮文档优先级后，E400 改作 MCP 规格补强，原任务顺延为 E401 并在交接中显式登记。
- VS Code 广泛用于多种职业，若直接加入软件画像关键词会误把普通前端/后端用户判成嵌入式工程师；因此只加入当前软件清单和子 Agent 目录，不改变“仅 VS Code → 不推断职业”的既有行为。

- VS Code 当前只是可发现的专业软件占位，不包含真实 MCP/CLI 连接、编辑器控制或新增写权限。
- 未运行 E2E/bench 或外部 LLM；文档检查结果见本轮交接。
- `git diff --check` 通过；`doc-lint` C1-C6/C8 通过，仍仅被需求文档第 19 行既有 provisional 超期阻断（2 FAIL / 0 WARN）。
