# 推进计划：重复修订生成 Skill 候选

> 日期：2026-09-12 · 分支：v0.2b · 状态：已完成（未提交）

## 目标

继续落实 §9.3：确定性归并重复“修改建议”，达到既有 [P-11] 后生成待确认 Skill 候选，不自动安装。

## 计划

1. 先补修订模式识别、候选审计与 gateway 闭环测试
2. 建立 append-only Skill 候选存储与状态流转
3. correct 反馈达到 [P-11] 后生成候选
4. Skill 设置页展示候选并允许用户保留或忽略

**验收标准**

- 只识别明确的确定性修订模式，不调用 LLM 猜测
- 同一回复改票只计最新 correct，同一用户同一模式只生成一个候选
- 候选初始为 proposed，用户可确认 accepted 或 rejected
- 接受候选不自动安装、启用或修改 Skill 权重

## 执行过程

### 改动

- 新增确定性修订模式识别与 append-only `SkillCandidateStore`；候选按用户与模式幂等生成，决定变更保留完整审计事件。
- `correct` 反馈按“每条回复最新值”归并；同类修订达到既有 [P-11] 后生成 proposed 候选。
- gateway 新增候选读取及接受/忽略接口；Skill 设置页展示待确认候选并明确接受不会自动安装。

### 遇到的问题

- 最初候选类型沿用了检测结果的 `key` 字段，与存储契约的 `pattern` 命名不一致；在首次 TypeScript 构建中暴露后统一为 `pattern`，未扩散到运行时。
