# 推进计划：S6 真实推送——CLI 装配与库加固（E244）

> 日期：2026-08-26 · 分支：v0.2b · 状态：计划中

## 目标

v1.0 S6（E225）库级骨架已收口（`src/repo/`：白名单/预检门禁/commit+push/审计 JSONL），但缺
「真实推送」运维入口：PushService 只能被代码注入调用，无 CLI。按 E240/E241/E243 同款流程，
本轮补齐 S6 真实推送 = CLI 装配：`repo:push`（`--dry-run` 只读计划 / `--yes` 真实推送）、
`repo:whitelist`（authorize/revoke/list 授权管理）、`repo:audit`（审计查看），并为 P-10 验收条件
「S6 真实推送」提供真实 git 协议端到端证据（本地裸仓库远程，语义对齐 INT-IM 的本地 mock server）。
真实 Gitee/GitHub 远程推送需 token + 显式 `--yes`，由用户按 E19/E93 先例执行。

## 背景与差距

- 需求锚点：§11.4 代码托管与远程协作（上传流程/白名单/审计/Token 不落盘）、§11.3 JSONL 审计、
  §10.2 命令白名单（git 破坏性子命令拒绝）、P-10「S6 真实推送」验收条件。
- 现状：`src/repo/` 已有 `types/repo-whitelist/push-audit/push-service`（E225，单测 15 条）；
  `scripts/push-to-hosts.ts`（E18/E93）是运维通道（dry-run/--yes/--create），两者互补。
- 缺口：S6 库无 CLI 入口；push 真实使用需用户手动装配；P-10 需要 S6 真实推送证据链。

## 计划

1. **新模块 `src/repo/cli.ts`**（编排可注入便于测试）：
   - `runRepoPush`：必须显式 `--dry-run`（只读 plan：变更清单/分支/URL/授权状态/缺 token 提示）
     或 `--yes`（真实推送）；参数校验拒绝非法 host / 仓库标识 / scope；输出 JSON，失败退出码 1；
   - `runRepoWhitelist`：`--list / --authorize / --revoke` 三选一，白名单 JSONL 落盘
     `data/repo-whitelist.jsonl`；
   - `runRepoAudit`：读取 `data/repo-push-events.jsonl`，`--limit N` 倒序输出。
2. **薄壳 `scripts/repo-push.ts` / `repo-whitelist.ts` / `repo-audit.ts`** + package.json
   `repo:push / repo:whitelist / repo:audit`（对齐 `scripts/market-run.ts` 风格）。
3. **PushService 加固**（真实边界，冒烟与集成实测发现）：
   - `cwd` 可注入（默认 process.cwd()）：`git add` 只添加实际存在的项目前缀，避免新仓库/局部
     仓库因缺失 pathspec 硬失败；
   - plan 分支名归一：本机 git `symbolic-ref --short HEAD` 实测返回 `heads/v0.2b`（只剥 refs/），
     剥 `heads/` 前缀对齐 push-to-hosts 既有写法。
4. **测试**：
   - 单测 `src/repo/cli.test.ts`（假 git 注入）：push 参数校验/dry-run 计划/缺 token 提示/
     --yes 成功/冲突退出码/whitelist 生命周期/audit 倒序/env 默认 owner/默认身份；
   - 集成 `tests/integration/repo-push-real.test.ts`（真实 git 二进制 + 临时工作区 + 本地裸仓库
     远程，runGit 包装仅重定向 push 目标 URL）：INT-REPO-001 授权后真实 add/commit/push +
     审计 ok:true 不含 token、002 未授权拒绝零 git 调用、003 远程冲突 conflict+rebase/merge 提示
     本地提交保留、004 CLI 编排 dry-run→authorize→yes push→audit 全链。
5. **文档与登记**：需求文档附录 A E244（无 §5/§6 参数变更 → bench:na(new-param)）；
   `docs/code-directory.md` / `docs/directory-structure.md` / AGENTS.md 目录地图（补 `src/repo/`）；
   package.json scripts；完成后补本计划「执行过程/结果」并在当天 handoff 登记。
6. **验证**：`npm run build` + `npm run test:all` 全绿；`doc-lint` 0 FAIL 0 WARN；
   真实冒烟 `npm run repo:push -- --dry-run`（本仓库只读计划）。

**验收标准**

- `--dry-run` 不执行任何 git 写操作，输出变更清单/分支/URL/授权状态/缺 token 提示；
- 真实推送必须显式 `--yes`；未授权仓库拒绝并提示先 authorize；
- token 仅环境变量注入不落盘、审计不含 token；git 命令逐条过 §10.2 白名单；
- 新增单测 ≥12 条 + 集成 ≥4 条；全量单测 + 集成全绿；doc-lint 0 FAIL 0 WARN。

### 遇到的问题

- Windows 下 apply_patch 经 .bat 传参内嵌引号会破坏解析：改用 PowerShell here-string 写文件。
- 集成测试踩两个真实 git 语义坑：① `git add <不存在的 pathspec>` 硬失败——临时工作区没有
  `.env.example` 等项目文件，暴露 PushService 缺 existsSync 过滤（顺带修复库）；② `git init --bare`
  的 HEAD 默认指向 unborn `master`，clone 会检出空分支导致推送「无关历史」被拒——setup 显式
  `symbolic-ref HEAD refs/heads/main`。
- `git status --porcelain` 对未跟踪目录折叠为 `?? src/`（而非逐文件），断言按目录前缀匹配。
- 单测假服务曾漏注入 auditPath，把测试审计写进真实 `data/repo-push-events.jsonl`：修复为临时路径，
  并清理了被污染的运行时文件（data/ git 忽略，不提交）。
