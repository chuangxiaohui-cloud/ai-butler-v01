# 推进计划：STM32-GCC 第二平台 MCP

> 日期：2026-09-14 · 分支：v0.2b · 状态：已完成

## 目标

以 CMake 为唯一构建入口接入 STM32-GCC 第二平台，从工程文件和 `compile_commands.json` 形成项目画像并支持受控 build；不开放 flash/串口。

## 计划

1. 只读发现含 STM32/ARM GCC 证据的 CMake 工程，解析 buildDir、CMake target、编译器和芯片宏。
2. 生成并原子保存项目画像；只有 CMake 可执行文件和 buildDir 均有证据时才登记结构化 build 引用。
3. 新增 stdio MCP 的 Discover/Inspect/Build 三工具，固定使用 `cmake --build`，接入白名单、mcp-agent 与 E404 工作流。
4. 补定向单测，同步需求、目录、验收和交接。

## 验收标准

- 不从目录名或模型猜芯片/工具链；多芯片宏或多 target 时保持未选择。
- buildDir 必须位于项目根内；调用不经 shell，参数固定，失败返回结构化诊断。
- 画像 `flash/serial` 恒为 `null`，本轮不存在烧录工具。
- 主项目 build、目标单测和 `git diff --check` 通过；`doc-lint` 不新增失败。不运行全量测试、集成/E2E、bench 或真实构建。

## 执行过程

### 改动

- 新增 STM32-GCC/CMake 工程发现、画像取证、固定 build 与 GCC 诊断解析。
- 新增 stdio MCP 三工具及注册表/配置白名单；异平台画像拒绝覆盖。
- mcp-agent 与领域工作流接入 STM32-GCC 只读盘点/build；build 禁止自动重试。
- 同步需求、目录、附录 A、验收与交接。

### 遇到的问题

- 画像 store 当前是一项目一文件；为避免覆盖 Keil 证据，E406 先拒绝异平台覆盖，字段级合并明确留给 E407。
- 既有 `doc-lint` C7 provisional 超期仍在，本轮不扩大处理。

## 结果

- `npm run build` 通过；定向测试 33/33。
- 未运行真实 CMake build、flash、串口、全量、集成/E2E 或 bench。
- 两个 MCP 配置 JSON 与 `git diff --check` 通过；`doc-lint` C1-C6/C8 通过，仅保留既有 C7 provisional 超期（2 FAIL/0 WARN）。
