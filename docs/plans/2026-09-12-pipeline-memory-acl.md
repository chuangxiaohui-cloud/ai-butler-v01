# 推进计划：pipeline 记忆资产 ACL

> 日期：2026-09-12 · 分支：v0.2b · 状态：已完成

## 目标

将 §8.1.2 的三栏固定记忆装备应用到问答 pipeline 的实际上下文注入，同时保持未显式传入栏位的 CLI 与旧调用兼容。

## 计划

1. 为 Chat Memory 与 Skill 经验的按栏位注入补失败测试。
2. 将 gateway 的合法栏位传入共享 pipeline，在用户上下文、历史问答、会话上下文和经验召回处执行读取侧 ACL。
3. 同步 E368、目录文档与交接，完成低成本验证。

**验收标准**

- 工程栏不向模型或 Skill 注入长期事实、历史问答和会话记忆，但保留用户身份/项目画像。
- 生活栏不检索、不注入 Skill 经验；知识栏可同时使用 Chat Memory 与 Skill 经验。
- 非法栏位请求在 gateway 返回 403；未传栏位的既有 API/CLI 调用保持兼容。
- 主项目构建与定向测试通过；不运行 E2E/bench，不提交。

## 执行过程

### 改动

- `PipelineOptions.mode` 接入三栏 ACL：工程栏清除可注入的事实/会话并跳过历史召回，生活栏跳过经验检索与透传，知识栏保留两类资产。
- 用户身份与当前项目不按 Chat Memory 清除，确保软件驱动职业画像继续服务各角色。
- `/api/ask` 校验并传入 mode；UI 对话、聊天确认卡、右侧裁决恢复都携带当前 mode。

### 遇到的问题

- pipeline 在意图路由前就会读取上下文，而输出 mode 在路由后才产生；本地 UI 已持有请求开始时的活动栏位，因此以显式 `opts.mode` 作为本轮读取边界。CLI/旧调用缺省 mode 时保留原行为，避免破坏既有入口。
- 裁决面板的批准恢复是独立 gateway 入口；已同步传递 mode，避免恢复执行绕过 ACL。

- 测试：pipeline 定向 4/4 + gateway 定向 3/3 通过。
