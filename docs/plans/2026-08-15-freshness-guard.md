# 推进计划：强时效查询旧闻防护

> 日期：2026-08-15 · 分支：v0.2b · 状态：已完成

## 目标

修复“中国空间站现在有哪几个航天员在太空”这类强时效问题返回旧闻（神舟十九/二十号）的根因：意图误判为 `factual` 导致时效权重过低，且合成层看不到证据发布日期。让 Agent 对“现在/当前/在轨/最新”类问题按新闻时效处理，旧闻不能冒充现状。

## 计划

1. 复测并定位：确认问题复现（返回 2025-04-26 腾讯旧闻，confidence 0.788）。
2. 新增时效敏感判定模块，接入意图分类、融合、合成三层。
3. 强时效状态问题规则优先走 `news` 意图 + `≤24h` 时间窗。
4. 融合层对强时效问题切新闻权重、90 天时效窗口、缺失日期降权。
5. 合成层注入今天日期、证据发布日期与“旧闻只能作背景”红线。
6. 补单测，跑 `npm run test:all`。
7. 真实复测，确认不再把旧闻当现状。
8. 登记 v2.5 附录 A（E81）、更新进度文档，doc-lint，提交推送。

**验收标准**

- 强时效问题不再把 2025 年旧闻当当前答案。
- 复测回答明确“截至今天暂无可靠更新/以官方为准”。
- 单测 242/242 + 集成 17/17，doc-lint 0 FAIL/0 WARN。

## 执行过程

### 改动

- 新增 `src/search/recency.ts`：`isRecencySensitiveQuery` 判定“现在/当前/今天/实时/最新/在轨/驻留”等时效敏感词。
- `src/search/stages/s2_classify.ts`：`今天/今日/实时/最新/行情/在轨/驻留/现状/现在有/目前有/当前有` 等强状态词规则优先归为 `news + ≤24h + 新闻源`。
- `src/search/fusion.ts`：强时效查询按 news 权重评分；时效窗口 90 天；无发布日期降为 0.15（普通查询维持 0.5/365 天）。
- `src/search/stages/s5_synthesize.ts`：系统提示注入“今天是 YYYY-MM-DD”；证据块带“发布于 日期/未知”；强时效问题追加“时效红线”：只有足够新的证据才能当现状，否则明确“截至今天暂无可靠更新”。
- 测试：新增 recency 单测 1 条、fusion 2 条、s2 1 条、s5 2 条。

### 遇到的问题

- 强时效查询按 news 权重后，旧闻 `timeliness=0` 且综合分可能低于 0.4 被丢弃；测试样本需保证相关性为 1 才能同时保留新旧两条做对比，已修正测试内容。

## 结果

- 验证：复测 `中国空间站现在有哪几个航天员在太空`，回答改为“截至今天暂无可靠更新/无足够新证据”，证据为 2026-06-17 腾讯新闻，不再引用 2025-04-26 旧闻；confidence 0.402，gate `low_confidence`（诚实门控）。
- 测试：单测 242/242 + 集成 17/17 全绿；doc-lint 0 FAIL/0 WARN。
