# 推进计划：表格 OCR 识别率提升（编号列模式纠正 E200 + 型号/名称词典 E201）

> 日期：2026-08-22 · 分支：v0.2b · 状态：执行中

## 目标

把表格 OCR（`office_image_ocr.py --table`）对 OCRtest.png 的识别率从实测基线（编号列 0%、中文列 85-96%）提升到编号列 ≥96%、中文列不劣化，并登记 E200/E201 纳入回归。

## 背景（实测，XLS 当基准）

- RapidOCR 原图：编号 0%（`XTE-VAIS-` 前缀全错）、备件名称 85%、型号 75%、数量 93%、单位 96%。
- 预处理通道（灰度→自动对比度→2x→锐化）：编号 84%（前缀全对，剩 8↔S 数字槽混淆 ~4 处），但中文列略降（名称 78%、型号 66%）。
- 结论：编号列取预处理通道、中文列取原图通道的**双通道融合** + **编号模式纠正**可把编号推到 ~96-100%；中文语义错（糖胶枪/整加型/闹机）由词典/后续引擎处理。

## 计划

1. E200：`preprocess_ocr_input` 标准预处理 + `--table` 双通道融合（代码列取预处理通道，其余取原图）+ 编号列模式纠正（数字槽混淆集 `{S/B→8, O/Q→0, I/l→1, Z→2}`，仅邻近数字时生效）。
2. E201：词典纠正（`--dict` 或默认 `data/ocr-dict.json`）——精确命中变体直接替换，长文本按相似度阈值模糊替换；短文本不模糊替换防误伤。
3. `--selftest` 纯函数自检模式 + office-daily TS 单测（不依赖 OCR 引擎）。
4. bench:B-20260822-09：OCRtest.png 真跑回归（融合+纠正后逐列准确率、耗时）。
5. 附录 A 登记 E200/E201、progress-handoff 加链接；doc-lint 0 FAIL 0 WARN。

**验收标准**

- `python scripts/office_image_ocr.py --selftest` 全绿。
- OCRtest.png 真跑：编号列 ≥96%、中文列不劣于基线（名称 ≥80%、型号 ≥70%、数量 ≥90%、单位 ≥90%）。
- `npm run build` + `npm run test:all` 全绿；`doc-lint` 0 FAIL 0 WARN。
- E199 页脚过滤等未提交改动不被破坏。

## 结果（2026-08-22 完成）

**实现要点（相对计划的 3 处修正，均有实测依据）**

1. 三通道文本融合替代双通道：实测 `suppress_faint_ink` 硬二值化会把 OCRtest.png 7px AA 小字边缘抹白（编号与中文列全毁，名称 43%），故结构仍用透字抑制通道 `cleaned`，非代码列文本改取 deskew 后灰度图（保留 AA，名称 98%），代码列取 2x 预处理通道（90%）。
2. 灰度通道补框仅限「所在行已有编号框」的数据行：E181 回归要求透字假框不进结构（bleed160 灰度通道会读出 `上海/合计/上海京` 等假框），无编号列表格整体不补框，四变体 merges+warning 与 E181 完全一致。
3. 补框 bbox 按网格行边界裁剪：跨行 bbox 会被 `detect_merges` 阶段 C 误判为跨行合并嫌疑（OCRtest.png 曾多出 3 条伪 `merged_conflict`），裁剪后回落预存 1 条。

**实测（bench:B-20260822-09）**：编号 0%→100%、数量 100%、单位 96%、名称 49/49、型号 43/45（96%），全部 ≥ 验收线；残差 3 处（登加型歧义/FR405 型号乱码/FR407 单位漏检）诚实登记。

**验证**：`--selftest` 13/13；office-daily 61 用例 60 通过 1 环境门控跳过；全量单测 589/590 + 集成 17/17；`npm run build` 通过；doc-lint 0 FAIL 0 WARN（附录 A 压缩 A.0 迁移段腾行数 + 登记 E200/E201）。
