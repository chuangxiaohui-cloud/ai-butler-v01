# 推进计划：回复轻量反馈持久化

> 日期：2026-09-12 · 分支：v0.2b · 状态：已完成

## 目标

落实 §9.3 的最小反馈闭环：UI 回复下方 👍/👎 写入本地持久化记录，并提供可审计明细与去重统计。

## 计划

1. 新增 append-only 回复反馈存储，复用既有 JSONL 轮转
2. 新增反馈写入、明细与统计 gateway API
3. UI 将现有 👍/👎 接入真实 API
4. 更新项目文档与当日交接

**验收标准**

- 反馈记录包含用户、会话、消息、问答、栏位、类型和时间
- 同一回复变更反馈保留事件历史，但统计只计最新值
- 非法反馈请求不落盘
- 主项目、UI 构建与定向单测通过

## 执行过程

### 改动

- 新增 `FeedbackStore`，复用通用 JSONL 追加、轮转与缓存读取。
- 每次改票追加新事件；按 user/conversation/message 取最新反馈生成统计。
- gateway 新增受鉴权保护的反馈写入、明细、最新状态与统计接口，并拒绝非法类型/栏位。
- UI 👍/👎 调用真实 API，写入成功后才更新状态；页面启动恢复当前会话最新选择。

### 遇到的问题

- 首次 gateway 定向测试命令的 name pattern 写错，实际未选中子测试；已用正确 pattern 重跑并通过，代码无需修改。
