# 推进计划：MCP 项目画像证据缓存与跨节点循环熔断

> 日期：2026-09-13 · 分支：v0.2b · 状态：已完成

## 目标

补齐 MCP 工程工作流的平台信息来源、跨节点自动修订总轮数上限与 `src/mcp/` 目录登记，避免模型重复猜测工具链或无界重复烧录。

## 计划

1. 在需求文档定义项目画像证据缓存、来源优先级与结构化工具引用，并登记 JSON Schema。
2. 新增 `[P-154]` 及轻量跨节点修订循环守卫，覆盖允许与熔断边界单测。
3. 同步 §13、工程目录文档、验收快照和当日交接。

**验收标准**

- 项目画像未知字段显式为 `null`，构建/烧录只能保存 `{agentId, toolName, args}`，不能保存裸命令字符串。
- 模型候选不能直接授权构建或烧录；达到 `[P-154]` 后返回携带串口日志与最近 diff 的人工接管要求。
- `npm run build`、目标单测与 `git diff --check` 通过；`doc-lint` 不新增失败。

## 执行过程

### 改动

- `configs/mcp-profiles/project-profile.schema.json` 与 `src/mcp/project-profile.ts`：定义项目画像字段、显式 null、结构化工具引用、证据来源优先级和模型候选动作门。
- `src/config/params.ts` 与 `src/mcp/workflow-guard.ts`：登记 [P-154] 并实现跨节点循环熔断与结构化人工接管要求。
- 需求 §4/§5/§11/§13、附录 A、目录地图、验收快照和当日交接：同步 E401 规格与诚实边界。
