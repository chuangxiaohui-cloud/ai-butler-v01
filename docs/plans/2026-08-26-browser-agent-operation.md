# 推进计划：Agent 浏览器操作能力（需求增补 E252）

> 日期：2026-08-26 · 分支：v0.2b · 状态：需求已落文档（代码实现后续迭代）
> 背景：用户调研 browser-use（GitHub，110.7k star、MIT、Python）后提出：v2.5 应增加「AI-Agent
> 像 Codex / browser-use 一样操作浏览器」的能力——不只读网页正文，还能在页面内点击/输入/导航/填表/下载。

## 计划

- 定位：现有浏览器会话（E74-E79 登录态继承 + E182 只读正文提取）升级为「读 + 交互」两层；
  只读路径与 `answer() -> { answer, confidence, evidence[], gate_triggered }` 稳定契约不变。
- 功能范围（§4.1.5）：`goto` / `click` / `type` / `select` / `scroll` / `hover` / `wait` / `download`；
  观察 = DOM 快照 + 截图回传；全程动作日志、可中止。
- 安全边界（对齐 §10）：
  - 动作白名单（§10.2 增「浏览器操作」类别），白名单外动作拒绝；
  - 高风险动作（表单提交/下载/跨域导航/写操作）过审批双闸（§10.5）；
  - URL 复用 SSRF 黑名单（§10.3 / url-safety）；
  - 页面观察（DOM 快照/截图）归 untrusted_data，prompt 注入防御适用（§10.5）；
  - 有界：单任务动作数 / 单步超时 / DOM 快照上限 → 新参数 [P-124]/[P-125]/[P-126]。
- 参考（4 点全落地）：① DOM 观察策略 → §4.1.5「观察与寻址」；② 动作白名单 → §10.2「浏览器操作」类别；③ 消息/token 管理 → §4.1.5「长任务编排」+ §8.3；④ 验收基准 → §4.1.5「验收基准」样例集（附录 C）。借思想不借底座；
- 落地形态 = **受限的浏览器操作 Skill（非通用 agent）**：域名白名单（manifest `domains`）+ 动作白名单（可收窄）+ 用户确认；§8.2.3 `browser` 权限联动；
  登记 `docs/borrowed-designs.md`。入口形态：内置浏览器交互层 + 市场 Skill `browser` 权限通道
  （E251 `@input` 通道已就绪，后续实现可用）。
