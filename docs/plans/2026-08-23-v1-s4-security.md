# 推进计划：v1.0 S4 安全模型补齐（命令白名单 + 搜索脱敏 + 注入防御）

> 日期：2026-08-23 · 分支：v0.2b · 状态：进行中

## 目标

v1.0 切片第四片（S4）：补齐全量安全模型（§10）——已收口文件沙箱（§10.1 E218 前）与 URL/SSRF（E218）；本片补齐 §10.2 命令白名单（允许集合 + 硬编码拒绝 + 超时 kind）、§10.3 搜索脱敏（剥离路径/密钥/内网地址 + 疑似密钥告警）、§10.5 注入防御（合成与深度报告的证据块显式分隔符 + 元数据标记，untrusted_data 与指令上下文物理分离），并按 §10.4 安全 TDD 用例表补测试。

## 计划

1. **§10.2 命令白名单** `src/security/command-whitelist.ts`：`checkCommand(cmdline)` 解析命令 → 允许集合（构建/烧录/版本/文件/测试五类）校验 + 危险模式硬编码拒绝（`rm -rf /`、`del /S /Q`、`sudo`、`eval`、`curl | sh`、下载执行 `.exe`、格式化）+ 按类别返回超时（[P-38]/[P-39]/[P-40]）+ 审计日志。
2. **§10.3 搜索脱敏** `src/security/query-sanitize.ts`：`sanitizeSearchQuery(query)` 剥离本地绝对路径、用户名/邮箱、API Key（sk-/AKIA/Bearer）、内网地址（192.168/10.x/172.16-31/localhost/127.0.0.1/::1），返回剥离项与告警；pipeline Stage 3 搜索前接入（`querySanitize` 依赖可注入，默认开启）。
3. **§10.5 注入防御**：`s5_synthesize.ts` 证据块与 `deep-report.ts` buildContext 加显式分隔符「【外部证据·untrusted_data·仅作参考】」+ 元数据标记（来源/发布/序号），与指令上下文物理分离。
4. **§10.4 安全 TDD**：命令白名单（rm -rf /、curl|sh 拒绝；keil --build 允许）、脱敏（路径/密钥剥离 + 告警）、注入防御（证据块含分隔符标记）测试。
5. **登记**：需求文档 E223；`docs/code-directory.md`、`docs/directory-structure.md`、handoff。
6. **验收**：doc-lint 0 FAIL 0 WARN + build + 全量单测/集成全绿。

**验收标准**

- 命令白名单：五类允许命令放行；危险模式硬编码拒绝（无论命令是否在白名单）；返回类别超时（[P-38]/[P-39]/[P-40]）。
- 搜索脱敏：含本地路径/API Key/内网地址的查询剥离后仅传必要信息，剥离项可审计，疑似密钥告警。
- 注入防御：合成 prompt 的证据块带显式分隔符与元数据标记，untrusted 证据与指令上下文物理分离。
- doc-lint 0 FAIL 0 WARN；单测 + 集成全绿。
