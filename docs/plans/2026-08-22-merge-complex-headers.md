# 推进计划：合并还原 + 复杂表头处理（E183）

> 日期：2026-08-22 · 分支：v0.2b · 状态：已完成

## 目标

承接 E177/E181（垂直组标签、deskew、透字抑制）。本期按已对齐的验收标准收口
“合并单元格还原 + 复杂表头处理”：以合成复杂表头样本库为验收素材，找出当前
`detect_merges` 仍失效的表头模式并修复；TSR 的 bbox/span 原始数据继续保留，
不重跑识别。

## 验收标准（已与用户对齐，回复“A”确认）

- 场景 A：跨行+跨列混合角落合并（如 `产品 A1:A3` + `销售 B1:D1`）能按 bbox/span
  直接还原，不重跑识别。
- 场景 B：多级分组 + 垂直标签共存（如整行标题下的垂直标签、两级分组+角落标签）输出
  与人工判定一致，无伪合并。
- 场景 C：无法判定的疑似区域全部转 `merged_conflict` warning 如实提示，答案给出
  “无法自动还原”而不是错结构。
- 回归：既有 10 张回归图 merges 与 E181 一致，`npm run test:all` + `doc-lint` 全绿。

## 计划

1. 合成样本库（`data/scan-e183/`，PIL 生成，复用 3 行 L 形测试的画图约定）：
   - S-A：`产品 A1:A3` + `销售 B1:D1`（跨行+跨列混合角落）。
   - S-B1：整行标题 + 垂直标签占表身（标题 A1:D1 + `产品 A2:A3` + 两级分组）。
   - S-B2：两级分组 + 角落跨行标签共存（`华东 B1:C1` + 角落 `产品 A1:A3`）。
   - S-B3：多级表头（三层）+ 垂直标签。
   - S-C：覆盖区有真实内容 → 必须转 `merged_conflict` warning。
2. 跑当前 `office_image_ocr.py --table` 建立基线，记录各样本 merges/warnings。
3. 按基线修复 `detect_merges` 失效模式（预计重点：标题行/covered 行下的垂直标签
   起点、垂直标签到表底的扩展、多级表头下相位 C 与角落合并的冲突）。
4. 测试：office-daily 新增真跑用例（每场景断言 xlsx `model.merges` + warning）。
5. 文档：附录 A 登记 E183、handoff、doc-lint。

## 执行过程

- 合成样本库 `data/scan-e183/`（4 张）：S-A 跨行+跨列混合角落、S-B1 整行标题+垂直标签、
  S-B2 角落+两级分组（与 E177 同构作回归）、S-B3 3 层表头（5 列对称布局消除歧义）。
- 基线：S-A/S-B2/S-B3 基本正确；S-B1 丢失 `产品 A2:A3`（标题行被并入或冲突跳过）。
- 根因 1：标题 OCR 文字落在第 2 列，`cell_items[0][0]` 为空 → `r_top` 扩展穿过被标题
  merge 覆盖的格子 → 与 covered 冲突被跳过。修法：`r_top` 循环遇到 covered 格停止。
- 根因 2：角落垂直标签下方同列无数据时被“下方有数据”守卫拦截。修法：第 1 列放宽为
  “下方其它列有数据即可”，并加 1×1 退化守卫。
- 根因 3：相位 C 内部空区间归属用文本中心，OCR 偏移会把对称空区间误分给相邻锚点
  （S-B3 华北 C2:D2 误并）。修法：改用槽位中心 `col_cx`，对称时平局归左侧。

## 结果

  S-B2 `A1:A3`+`B1:C1`；S-B3 `A1:A3`+`B1:E1`+`B2:C2`+`D2:E2`，零 warning。
- 测试：office-daily 新增 1 条真跑 3 变体（xlsx 读回 `model.merges` + 锚点格 + 答案计数断言）；
  主项目 build；单测 537/537 通过 + 1 条 fitz 门控用例按环境跳过 + 集成 17/17 全绿；
  doc-lint 0 FAIL 0 WARN。既有 10 张回归图 merges 与 E181 一致，零回归。
- 场景 C（无法判定 → merged_conflict warning + “无法自动还原”）沿用 E181 的透字 90 用例，
  本次回归通过。
