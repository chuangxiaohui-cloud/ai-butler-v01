# 推进计划记录

每次推进或修改，先在这里写计划，再执行，最后补结果。这样任何一次改动都有“计划 → 执行 → 结果”三段可追溯记录。

## 目录约定

- 文件名：`YYYY-MM-DD-<主题>.md`，例如 `2026-08-15-browser-cdp.md`。
- 模板：[`_template.md`](./_template.md)，新建计划时复制它。
- 计划文档只记录本次推进；每天的汇总仍写 `docs/2026-08-XX-progress-handoff.md`。

## 流程

1. **动手前**：复制模板，写清目标、计划步骤、验收标准，文件名带当天日期。
2. **执行中**：在“执行过程”里记录关键命令、改动文件、遇到的问题与解法；过程性日志不追求事无巨细，但必须能让后来的自己或 Agent 还原现场。
3. **完成后**：补“结果”一节（验证命令、测试数、提交 hash、推送状态、遗留事项），并在当天 `progress-handoff.md` 里加一行链接。
4. **权威变更**：涉及需求/参数/行为变更的，同时登记到 v2.5 附录 A（E 编号）；机器原始证据进 `data/trajectory.jsonl`、`bench/search-metrics.jsonl` 等。

## 与现有记录的关系

| 记录 | 内容 | 何时写 |
|------|------|--------|
| `docs/plans/YYYY-MM-DD-<主题>.md` | 本次推进的计划、执行、结果 | 动手前创建，完成后补全 |
| `docs/2026-08-XX-progress-handoff.md` | 每天做了什么、下一步做什么 | 每天收尾 |
| v2.5 附录 A | 权威变更台账（E 编号） | 涉及需求/参数/行为变更时 |
| `data/trajectory.jsonl` | 问答轨迹事件 | 程序自动 |
| `bench/search-metrics.jsonl` | 搜索耗时/成功/超时 | 程序自动 |
