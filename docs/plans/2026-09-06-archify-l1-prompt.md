# 推进计划：Archify L1 提示级补全（架构补全 + 假设入卡 + 单图型纪律，E355）

> 日期：2026-09-06 · 分支：v0.2b · 状态：完成（未提交，待 owner 真机验收）
> 关联：owner 讨论「提示词准不准 / vibe coding / AI 面向非专业」后拍板 L1——不改全局 System Prompt（Archify 是触发式 Skill，塞全局会污染秘书/产品经理等角色），只改 archify 自身生成提示；「高质量图 = 好剧本 + 渲染器」，短描述应被模型按工程常识展开并让补全可见可撤。

## 目标

用户在 5173 给短问题（例「画个订单系统」「画个发布流程」）时，Archify 也能产出层次/阶段完整的图：
- 模型先当资深架构师展开用户意图（短句→常用件/完整闭环），不再忠实直译关键词；
- 所有「替用户补的内容」写进 cards「假设」开头说明（可见、可撤），用户点名或排除的严格照办；
- 一次只画当前图型，描述里混杂的其他图型主题不并入本图；
- 核心组件保持 8-12 个，不编造具体技术品牌/协议。

## 方案（最小，只动 prompt.ts + 测试）

1. `src/skills/archify/prompt.ts` `buildGenerationPrompt`：在 COMMON_RULES 与 type 特有编排之间插入「## 架构补全与假设（内容层）」小节：
   - 展开原则：高流量/对外/写密集默认考虑网关/缓存/消息队列/读写分离；流程类默认 构建→测试→发布→上线→监控 完整闭环；「简单/单体/内部」不堆件。
   - 假设纪律：补全必须写进 cards 且以「假设」开头；用户点名/排除的严格照办。
   - 单图型纪律：只画当前 type；混入的其他图型主题最多在 cards 提一句可单独成图。
   - 诚实：不编造技术品牌/协议，写通用名或标注示例；核心组件 8-12 个。
2. 不动的部分：detectDiagramType、修复提示、渲染链路、UI、路由、confirm 语义均不改。
