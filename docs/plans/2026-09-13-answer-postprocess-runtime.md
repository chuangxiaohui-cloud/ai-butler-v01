# 推进计划：answer_postprocess Skill 运行时契约

> 日期：2026-09-13 · 分支：v0.2b · 状态：已完成（未提交）

## 目标

继续落实 §9.3：建立最小、确定性的 `answer_postprocess` Skill 运行时契约，并接入共享 pipeline 的 Stage 6 回答落盘前位置；安装入口继续关闭。

## 计划

1. 先补运行时规则顺序、失败隔离与 pipeline 接线测试
2. 新增回答后处理规则/运行时接口
3. 在 Stage 6 最终回答写记忆与轨迹前执行规则
4. 补齐 E382 文档记录并做便宜验证

**验收标准**

- 规则按注册顺序执行，空输出与异常不破坏原回答
- pipeline 返回、会话记忆与轨迹使用同一后处理结果
- 无规则时现有行为不变
- 不读取候选草案、不安装或自动启用任何规则

## 执行过程

### 改动

- 新增 `AnswerPostprocessRuntime` 与规则契约；规则顺序执行，仅实际改写回答时登记 Skill 名称。
- 单条规则异常、空输出、未改动以及运行时整体异常均保留当前答案，不阻断后续 pipeline。
- 运行时接入 Stage 6、L0 记忆和轨迹写入之前；最终返回增加实际生效的 `postprocessSkillNames`。

### 遇到的问题

- pipeline 存在多条直达返回路径；本轮按“最小契约”只接 Stage 6 搜索/合成主路径，避免为尚未安装的规则大范围改写所有返回分支。

## 结果

- `npm run build` 通过；answer-postprocess + pipeline 定向测试 80/80；覆盖规则顺序、失败隔离、最终返回、会话记录与轨迹摘要一致。
- `git diff --check` 无空白错误；`npm run doc-lint` 的 C1–C6/C8 通过，仍仅被第 19 行存量 provisional 示例超期阻断。
- 边界：规则仅由调用方显式注入；未读取候选草案、未新增安装入口、未自动启用。零外部 LLM（¥0），未跑 E2E/bench，未提交。
