# 推进计划：Skill 候选草案预览

> 日期：2026-09-12 · 分支：v0.2b · 状态：已完成（未提交）

## 目标

继续落实 §9.3：把用户已接受的修订候选转换为确定性、只读、可审阅的 Skill 草案，不落盘安装。

## 计划

1. 先补草案生成与 gateway 访问门禁测试
2. 为 accepted 候选生成稳定的 manifest、规则与证据预览
3. 在 Skill 设置页展示草案，明确当前不可安装
4. 补齐 E381 计划、目录与交接记录

**验收标准**

- proposed/rejected 候选不能生成草案
- 草案生成不写文件、不注册 Skill、不改变候选审计流
- 用户只能读取自己的候选草案
- UI 明确展示当前运行时不支持纯回复规则安装

## 执行过程

### 改动

- 新增纯函数草案生成器，为 accepted 候选构造稳定名称、版本、无权限声明、回答后处理规则、样本证据与 Markdown 预览。
- gateway 新增受鉴权保护的只读草案接口；未接受候选返回冲突，其他用户候选按不存在处理。
- Skill 设置页保留 accepted 候选并提供草案预览，显示 manifest 摘要、规则、证据与安装阻断原因。

### 遇到的问题

- 现有市场 Skill 执行器只支持命令/浏览器步骤，无法执行纯回复风格规则；草案据实标记 `installable: false`，没有生成空 handler 或伪装成可安装包。

## 结果

- 主项目与 UI build 通过；候选、草案与 gateway 定向测试 46/46；`git diff --check` 无空白错误。
- `npm run doc-lint` 仍被存量 C7 阻断：需求文档第 19 行 provisional 示例超期；C1–C6/C8 通过。
- 边界：本轮全程只读生成草案，不写安装目录、不注册 Skill、不改变候选状态；零外部 LLM（¥0），未跑 E2E/bench，未提交。
