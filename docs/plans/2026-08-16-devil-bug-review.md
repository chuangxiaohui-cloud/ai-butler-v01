# 魔鬼训练 v2.5 缺陷清单审阅（模型能力 vs 系统级故障）

> 日期：2026-08-16 | 审阅对象：
> - `bench/devil-v25/魔鬼训练_模型能力问题参考.csv`（8 条）
> - `bench/devil-v25/魔鬼训练_系统级故障Bug清单.csv`（35 条）
> 核对基准：`bench/devil-v25/results.jsonl`（整理版全量 122 条真实返回）

## 1. 结论先行

两份清单结构合理、覆盖完整，**35 条 Bug 全部可复现**，8 条“模型能力问题”也可复现。43 条 0 分 = 35 条系统级故障 + 8 条能力/兜底问题，与定稿评分完全对账。

需要修正两处措辞：

1. **“溺水救援误匹配”只适用于 EC26**。EC04/EC12/EC13 的真实返回是通用“人身急救模板”（先冷静、拨打 120/119/110、判断伤者），只有 EC26 手机进水命中了“溺水救援模板”。根因相同（紧急关键词过宽），但描述应更准确。
2. **“完全拒答”不是模型能力问题**。ET05/ET06/ET14/ET30/EC06/EC23/P03 的真实返回是 `我暂时无法确认这个问题...` 或 `我没把握您要做什么...`，属于低置信兜底/澄清话术误触发；C05 则被误路由到“指代澄清”（问芯片型号）。它们更像系统兜底层问题，建议改名为“低置信兜底/澄清误触发”，把真正的“知识能力不足”单独统计。

## 3. 逐条核对发现

- **BUG-001..024（路由）**：真实返回均为 `您希望我按哪个任务范围排期` / `您想让我处理哪个方向` / `这份需求先按哪个方向起草` / `您指的是哪一个方案` / `技术方案需要先拆哪个部分`，即“回答型意图”被误判为“建任务/写文档/发消息”，24 条全部命中。
- **BUG-025..031（JSON 泄露）**：真实返回含 `{"error":"missing_time"}`、`{"ok":true,"recipient":"联系人"...}`、`content_writer_requires_llm`，未做异常兜底转换，7 条全部命中。
- **BUG-032..035（安全）**：危险/非法请求未进安全拒绝分支，而是被紧急路由抢走；EC04/EC12/EC13 回通用人身急救模板，EC26 回溺水救援模板，4 条全部命中。
- **能力清单 8 条**：7 条是 `我暂时无法确认这个问题` / `我没把握您要做什么`，1 条（C05）是“指代澄清”误触发，与“模型知识不足”的定性不完全一致。

## 4. 建议下一步

1. **把清单转成回归用例**：每个 Bug 至少对应一条 pipeline 单测或 `bench/devil-v25` 回归断言，修复后重跑确认 35 条全部转绿。
2. **修复优先级**：BUG-032..035（安全）> BUG-025..031（JSON 泄露）> BUG-001..024（路由）；8 条兜底/澄清问题并入路由修复一起处理。
3. **清单加字段**：建议补充“复现返回摘要”“关联测试 ID”“修复状态”，并建一个校验脚本让清单与 `results.jsonl` 保持同步。
4. **修正措辞**：按本审阅第 1 节把“溺水救援误匹配”拆成“通用人身急救模板误匹配 + 溺水模板误匹配”，把“完全拒答”改为“低置信兜底/澄清误触发”。
