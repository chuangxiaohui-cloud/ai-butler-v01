# 推进计划：真实扫描件复杂表头收口——左上角垂直标签 + 斜跨/嵌套多层（E184）

> 日期：2026-08-22 · 分支：v0.2b · 状态：已完成

## 目标

承接 E183（复杂表头合并还原）。本期收口真实扫描件复杂表头中最常见的剩余失效模式：
**左上角垂直组标签**（标签文本在第 1 行、向下跨越多个表头行，如“产品 A1:A3”），
以及与其共存的**斜跨/嵌套多层**组头（行 0 横向组头 + 下级标签行）。全部改动在
`detect_merges` 内完成，复用 TSR 已保留的 bbox/span，不重跑识别。

## 背景（基线确认）

用合成样本跑当前 `office_image_ocr.py --table` 确认失效点：

- T1（`产品` A1:A2 + 行 0 组头 `2024 B1:C1`/`2025 D1:E1` + 行 1 子标签）：当前只还原
  横向组头，`产品 A1:A2` 丢失，且首个数据格 `手机`（行 2 列 0）被相位 B 截断守卫误报
  `merged_conflict` warning（“疑似跨 3 行垂直合并…无法自动还原”）。
- T2（斜跨阶梯：`产品` A1:A3 + 行 0 组头 + 行 1/2 子标签）：`产品 A1:A3` 丢失。
- 根因：相位 B 只处理“锚点在行 1..band_v-1、向上扩展”的垂直标签；标签文本在第 1 行时
  完全没入口。且相位 C 的横向空隙模式把垂直标签列计入 `row_filled`，行 0 只有单个内部
  空隙时（如 `产品 | 2024 | 空 | 2025`）会被模式检查提前跳过，漏掉 `2024 B1:C1`。

## 计划

1. `scripts/office_image_ocr.py` `detect_merges` 新增**相位 B0**（位于相位 A 之后、相位 B
   之前）：第 1 行锚点向下扩展——
   - 锚点 (0, c) 有文本、未被 covered、直接下方同列为空；
   - 向下扩展连续空格（遇到 covered/内容停止）得 r1；
   - 守卫 1：扩展区同列下方（r1+1..rows）必须有内容（否则是空表尾/末行缺值）；
   - 守卫 2：扩展区行（1..r1）其它列至少有一个**非数字**子标签（表头带证据，避免把
     数字数据行的缺值格当标签）；
   - 纯数字锚点跳过；冲突校验通过后产出 `{row:0, col:c, rowSpan:r1+1, colSpan:1}`，
     标 covered。
2. 相位 B 保持原逻辑（锚点在行 1..band_v-1 向上扩展）；B0 先行使数据格（如 `手机`）
   上方被 covered，截断守卫不再误报。
3. **相位 C 垂直列排除**：统计 `row_filled` 与空隙区间时，跳过被垂直合并（rowSpan>1 且
   colSpan==1）覆盖的列，避免左上角标签破坏行 0 横向组头模式。
4. 测试：office-daily 新增 1 条真跑 3 变体（T1 左上角标签+行 0 组头、T2 斜跨阶梯、T3 嵌套 4 层），
   xlsx 读回 `model.merges` + 答案计数断言；回归既有 10 张回归图 + 缺值数据行不误并 +
   E181/E183 用例。
5. 文档：附录 A 登记 E184、skills README、handoff、doc-lint。

**验收标准**

- T1 → `产品 A1:A2` + `2024 B1:C1` + `2025 D1:E1`，零 warning，答案“已还原 3 处”。
- T2 → `产品 A1:A3` + `2024 B1:C1` + `2025 D1:E1`，零 warning，答案“已还原 3 处”。
- 缺值数据行（行 1 列 1 空缺）不产生任何合并，既有无网格回退/2×2 角落/L 形/3 行垂直
  标签/倾斜纠正/扫描件鲁棒性/复杂表头用例 merges 输出全部不变。
- `npm run build` + `npm run test:all` + `doc-lint`（0 FAIL 0 WARN）全绿。

## 执行过程

- 基线确认（当前代码）：T1（产品 A1:A2 + 行 0 组头）只还原横向组头，`产品 A1:A2` 丢失且首个
  数据格 `手机` 被相位 B 截断守卫误报 `merged_conflict` warning；T2（斜跨阶梯 `产品` A1:A3）
  垂直标签丢失；T3（嵌套 4 层 `产品` A1:A3 + `2024 B1:E1`）行 1 组头 `上半年 B2:C2`/`下半年
  D2:E2` 因空隙模式检查被跳过。
- 改动（`scripts/office_image_ocr.py` `detect_merges`）：
  1. 新增相位 B0（相位 A 之后、相位 B 之前）：第 1 行锚点垂直标签向下扩展——直接下方同列为空、
     向下扩展到同列连续空格底部；四道守卫：同列下方（扩展区外）必须有内容（防空表尾/末行缺值）、
     扩展区行其它列至少一个非数字子标签（防数字数据行缺值）、锚点文本不在表内其它格重复出现
     （防扫描件透字残影，子串匹配覆盖残影与真实文本粘连）、锚点列右侧扩展区行有内容（防右缘表头
     列下方缺值，如 2×2 角落的 `数量 C1:C2`）。
  2. 相位 C：统计 `row_filled` 与空隙区间时排除被垂直合并（rowSpan>1 且 colSpan==1）覆盖的列，
     左上角标签不再破坏行 0 组头模式检查。
  3. 相位 C：空隙模式不成立但“锚点全部非数字且空隙全部为单格”时按嵌套多层表头放行，逐空隙并入
     最近锚点（`上半年 | 空 | 下半年 | 空 | 上半年 | 下半年`）。
- 遇到的问题：
  - B0 首次实现后 2 条既有真跑回归——2×2 角落 `数量 C1:C2` 被误并（右缘表头列下方缺值）、
    扫描件鲁棒性 bleed90 透字残影 `上海` 被误并（残影与真实文本合并成 `上海京`，精确匹配守卫
    失效）。分别补“锚点列右侧有内容”与“子串匹配残影守卫”修复，回归归零。
  - 测试图列宽不足导致 OCR 把相邻格文本并成一个 span，加宽列并缩小字号（26px、列宽 150px）解决。

## 结果

- 真跑 3 变体全部按人工判定输出：T1 `A1:A2`+`B1:C1`+`D1:E1`；T2 `A1:A3`+`B1:C1`+`D1:E1`；
  T3 `A1:A3`+`B1:E1`+`F1:G1`+`B2:C2`+`D2:E2`，零 warning。
- 测试：office-daily 新增 1 条真跑 3 变体（xlsx 读回 `model.merges` + 锚点格 + 答案计数断言）；
  主项目 build；单测 538/538 通过 + 1 条 fitz 门控用例按环境跳过 + 集成 17/17 全绿；
  doc-lint 0 FAIL 0 WARN（附录 A 948/950 余 1 行）。既有 10 张回归图 + E181/E183 用例
  merges 输出与 E183 一致，零回归。
- 已知边界：垂直标签文本在行 0 且扩展区行其它列全为数字（如纯两列“产品/数量”竖排标签）不合并；
  数字数据行中间缺值（如 `手机 | 空 | 300`）仍按既有水平启发式处理；跨页大表拼接（多页表头
  重复）留待下期。
