# 项目事务冲突清单与仲裁契约

## 目标

- 提交前一次性收集全部文件冲突，而不是只返回第一个错误字符串。
- 每条冲突提供快照、当前和目标内容摘要及存在状态，不暴露文件正文。
- 返回固定仲裁选项：保留外部版本、使用事务版本、取消整批；默认取消整批且必须由用户确认。

## 非目标

- 本轮不执行任何仲裁选择，不自动覆盖或合并文件。
- 不接 gateway/UI 确认入口，不写 decision log。
- 不接 project-writer 多文件输入或 EDA 写操作。

## 验收标准

- 同一事务多个文件变化时返回完整冲突清单，目标文件零写入。
- 覆盖→修改、覆盖→删除、新建→被外部创建三种冲突均能区分。
- 每条冲突含 snapshot/current/proposed SHA-256；仲裁契约选项固定、默认取消、要求确认。
- 无冲突提交与 E394 自动回滚、operation log 行为保持通过。

## 执行过程

### 改动

- `ProjectTransactionEntry` 与快照清单新增目标内容 SHA-256，提交前同时比较路径存在状态和当前摘要。
- 冲突预检改为扫描整批变更，区分外部修改、外部删除和外部创建，并一次返回完整冲突清单。
- 新增只读仲裁数据契约，固定提供“保留外部版本 / 使用事务版本 / 取消整批”，默认取消整批且要求用户确认。
- 冲突结果只携带路径、存在状态和 snapshot/current/proposed 摘要；不携带文件正文，也不执行任何选择。

### 遇到的问题

- 仅比较摘要无法识别“原本不存在、现在出现目录”的冲突；改为独立比较存在状态，目录也会被安全归为外部创建或修改。
- 本轮只定义仲裁契约。如果直接执行 `use_transaction`，会越过用户确认与再次校验，因此明确留到后续轮次。

## 结果

- `npm run build`：通过。
- 定向测试：18/18 通过，其中项目事务 7/7、operation log 4/4、既有 project-writer 7/7。
- 多冲突用例验证目标零写入，三类冲突完整返回，固定选项、默认取消和确认标记稳定，审计日志不含目标正文。
- 未运行 E2E、全量 bench 或真实 EDA 写操作；未提交。
