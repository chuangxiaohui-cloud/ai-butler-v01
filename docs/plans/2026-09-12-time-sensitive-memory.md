# 推进计划：时间敏感记忆过期提示

> 日期：2026-09-12 · 分支：v0.2b · 状态：已完成

## 目标

补齐 §8.3.2 的时间敏感信息治理：库存、价格、版本、排期事实到达既有 [P-93] 老化检查点后仍可追溯，但必须标注“可能已过时”并建议重新确认。

## 计划

1. 新增确定性时间敏感分类与过期判断，复用 [P-93] 的 90 天检查点
2. 为 `user_facts` 无损补齐时间分类/到期时间，并接入新增、纠正、读取
3. 在 prompt 注入、记忆 API 与 UI 中透出过期警告
4. 更新项目文档与当日交接

**验收标准**

- 四类时间敏感事实可识别，普通事实不误标
- 到期事实仍能查询，但注入内容明确提示“可能已过时，建议重新确认”
- 旧数据库补列后保持兼容；纠正事实重新计算时效元数据
- 主项目、UI 构建与定向单测通过

## 执行过程

### 改动

- 新增 `time-sensitive-memory.ts`，保守识别库存、价格、版本、排期四类事实。
- 复用 [P-93] 的 90 天长期事实老化检查点，未新增 PARAM。
- `user_facts` 新增 `temporal_kind`、`expires_at`，旧库原位补列并回填已有时间敏感事实；新增/纠正事实同步刷新。
- `MemoryFact`、记忆 API 与 UI 透出 stale/到期信息；prompt 对到期事实改用重新确认警告。
- 文化回复专用后处理不再把到期事实当作确定偏好。

### 遇到的问题

- 首次单测误把创建时间传给只接受到期时间的判断函数；修正测试调用后通过，生产存储链路无需改动。
