# 推进计划：扫描件 PDF OCR

> 日期：2026-08-15 · 分支：v0.2b · 状态：已完成

## 目标

让无文本层的扫描件 datasheet 也能被二次取证读取：`scripts/pdf_text.py` 检测到“有图片但无文本”的页面时，用 PyMuPDF 渲染页图并调用 OCR 识别，把识别文本并入返回结果；OCR 引擎采用 RapidOCR ONNX（官方 PyPI 可安装的轻量方案，替代尚未安装的 PaddleOCR）。

## 计划

1. 确认本机 Python/pip 与 OCR 包可用性（官方 PyPI 有 `rapidocr_onnxruntime 1.4.4`）。
2. 安装 `rapidocr_onnxruntime` 到 PATH 上的 Hermes venv（`python` 实际指向它）。
3. 改 `scripts/pdf_text.py`：扫描页渲染 PNG → RapidOCR 识别 → 并入 text；返回 `ocr: true/false`；OCR 未安装时保持诚实报错信息。
4. Node 侧 `document-parser.ts`：扫描件 OCR 有文本就返回，无 OCR 时给出“OCR 引擎未安装”的明确提示。
5. 用 TPS5430 第一页渲染成纯图片 PDF，做真实 OCR 冒烟。
6. 补/改单测，跑 `npm run test:all`。
7. 登记 v2.5 附录 A（E84）、更新进度与计划文档，doc-lint，提交推送。

**验收标准**

- 纯图片 PDF 能被 OCR 出可读文本（至少命中关键参数词）。
- 无文本层且无 OCR 引擎时返回明确安装指引，不静默。
- 单测全绿，doc-lint 0 FAIL/0 WARN。

## 执行过程

### 改动

- `scripts/pdf_text.py`：无文本层且有图片的页渲染 2x 页图 → RapidOCR（ONNX）识别 → 并入 text；返回 `ocr/ocrAvailable/ocrError`；`PDF_OCR=0` 可禁用 OCR 便于测试。
- `document-parser.ts`：OCR 引擎缺失时给出 `pip install rapidocr_onnxruntime` 安装指引，OCR 失败时诚实报错。
- 环境：`python -m pip install rapidocr_onnxruntime`（官方 PyPI，Hermes venv）。

### 遇到的问题

- 清华镜像没有 `rapidocr_onnxruntime`，改用官方 PyPI。
- PATH 上的 `python` 是 Hermes venv，OCR 必须装进该环境，否则 Node 子进程找不到。
- `fitz` 在 `main()` 里局部导入，`ocr_page()` 引用 `fitz.Matrix` 抛 `NameError` 被静默吞掉；在 `ocr_page()` 内补 `import fitz` 解决。
- RapidOCR 对 RGB 数组和 BGR 数组都能识别，无需转通道。

## 结果

- 验证：TPS5430 第一页渲染成纯图片 PDF，OCR 提取 1,299 字符并命中 `TPS5430`/`5.5V`/`500kHz`；`PDF_OCR=0` 时返回“OCR 引擎未安装”安装指引。
- 测试：单测 250/250 + 集成 17/17 全绿；doc-lint 0 FAIL/0 WARN。
- 提交：<hash> · 推送：Gitee / GitHub
- 遗留事项：OCR 单页约 20 秒，多页扫描件偏慢；后续可只对含图片页 OCR 并限制页数；RapidOCR 与 PaddleOCR 精度可再对比。
