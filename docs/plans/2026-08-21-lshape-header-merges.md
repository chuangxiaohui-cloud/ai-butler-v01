# 推进计划：L 形 / 跨行+跨列组合复杂合并区域还原（E176）

> 日期：2026-08-21 · 分支：v0.2b · 状态：已完成

## 目标

承接 E175（整行标题 + 前两行分组）。E175 的“组间空隙”启发式只做水平扩展，且对
单文本行太贪婪：真跑显示两类缺陷——①2×2 角落合并（`项目` 跨 A1:B2）被误还原为
整行（`数量` A1:C1、`项目` A2:C2）；②L 形表头（`产品` A1:A2 + `地区` B1:C1）的
垂直组标签 `产品` 完全没检出。本期新增垂直/角落合并相位，并收紧水平相位的覆盖
守卫，避免与角落合并冲突。

## 计划

1. `scripts/office_image_ocr.py` `detect_merges` 顶部表头相位重构为三段：
   - 阶段 A：整行居中标题（E175 原逻辑，先执行，覆盖整行防冲突）。
   - 阶段 B（新增 E176）：垂直组标签 / 角落合并——锚点在表头带（第 1 行）且
     上方同列为空、下方同列有内容时，向上扩展到连续空格顶部，再向右扩展同行
     空格（要求整列矩形全空且扩展列下方有数据），得到 `rowSpan × colSpan`
     矩形；锚点为纯数字（数据行）时跳过；与 covered 冲突则放弃。
   - 阶段 C：组间空隙水平启发式（E173/E175 原逻辑）——行级 covered 守卫改为
     逐空区间守卫（否则角落合并会挡住同行其它组头，如 `地区` B1:C1）。
2. 真跑：2×2 角落图 → `项目` A1:B2（`数量` 保持单格）；L 形表头图 →
   `产品` A1:A2 + `地区` B1:C1。
3. 测试：新增 2 条真跑（角落 2×2、L 形表头），xlsx 读回 `model.merges` 断言；
   回归既有 5 用例 + E175 组合表头共 6 用例 merges 输出一致。
4. 文档：附录 A 登记 E176（继续压缩旧条目腾行）、skills README、handoff、
   doc-lint。

**验收标准（本次对齐）**

- 2×2 角落图 → xlsx `A1:B2` 共 1 处合并（`数量` 不误并）。
- L 形表头图 → xlsx `A1:A2` + `B1:C1` 共 2 处合并。
- 既有 6 用例（2×2、宽表头、两级表头、跨行、无网格回退、E175 组合表头）
  merges 输出与 E175 完全一致。
- 缺值数据行（3 文本 1 空隙）不误并；数据行纯数字锚点不触发垂直合并。
- `npm run build` + `npm run test:all` + `doc-lint`（0 FAIL 0 WARN）全绿。


## 结果

- `detect_merges` 顶部表头相位重构为三段（A 整行标题 / B 垂直+角落 / C 水平空隙）。
- 阶段 B：垂直组标签/角落合并——锚点上方同列空格且下方有数据时向上扩展、再向右
  扩展同行空格成 `rowSpan × colSpan` 矩形；纯数字锚点跳过；新增“上方同列格在同行
  水平组头向右延伸范围内则拒绝”护栏，修复两级表头下“杭州/天津”被误并的回归。
- 阶段 C：行级 covered 守卫改为逐空区间守卫，角落合并不再挡住同行其它组头。
- 真跑：2×2 角落图 → `项目` A1:B2（`数量` 保持单格）；L 形表头图 → `产品` A1:A2
  + `地区` B1:C1；既有 2×2/宽表头/两级表头/跨行/无网格/组合表头 6 用例 merges
  输出与 E175 完全一致。
- 测试：office-daily 新增 2 条真跑（角落合并、L 形表头；L 形断言按集合比较，
  因 exceljs write→read 往返会重排 merges 顺序）；主项目 build；单测 530/530
  通过 + 1 条 fitz 门控用例按环境跳过 + 集成 17/17 全绿；doc-lint 0 FAIL 0 WARN。
- 已知边界：3 行及以上的垂直组标签（如 `产品` A1:A3）本期未覆盖，留待下期。
