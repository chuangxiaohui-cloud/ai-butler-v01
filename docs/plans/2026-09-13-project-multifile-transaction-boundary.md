# 项目多文件事务边界

## 目标

- 为纯文件工程建立项目级事务：全量预检、原内容快照、同目录暂存、显式提交。
- 预检或暂存任一失败时，目标文件保持完全不变。
- 提交前检测文件是否自快照后被外部修改；冲突时拒绝整批提交。
- 提交中途失败时诚实返回已提交/未提交清单并保留快照，供下一轮恢复。

## 非目标

- 本轮不实现提交中途失败后的自动批量回滚与冲突仲裁。
- 不修改 project-writer 自然语言格式，不接 Keil/KiCad/其他 EDA 写操作。
- 不执行命令，不新增外部依赖。

## 关键约束

- 多文件系统不存在通用跨文件原子 rename；本轮“原子边界”定义为：全部文件成功暂存且通过提交前一致性检查后，才开始触碰目标文件。
- 一旦进入逐文件 rename，底层故障仍可能产生部分提交；必须返回 `partial_failed`，不得误报成功。

## 验收标准

- 覆盖两文件成功、越界/重复预检失败、暂存失败零目标写入、提交前冲突零目标写入、提交中断诚实状态。
- 快照 manifest 能区分覆盖与新建，并记录原内容摘要；事务目录位于 `data/writer-transactions/` 或测试注入目录。
- 主项目构建与事务定向单测通过；不运行 E2E/bench。

## 执行过程

### 改动

- 新增 `src/security/project-transaction.ts`，提供 `prepareProjectTransaction()` 与 `commitProjectTransaction()` 两阶段接口。
- prepare 先完成整批路径白名单、内容类型、重复路径和目标类型检查，再创建项目级快照；覆盖文件保存备份与 SHA-256，新建文件明确记录 `existed=false`。
- commit 先比较当前内容与快照摘要，再把全部新内容写入目标同目录临时文件并回读；只有全部暂存成功才开始逐文件 rename。
- 暂存失败返回 `stage_failed` 且目标零写入；快照后变化返回 `conflict` 且目标零写入；提交中断返回 `partial_failed`、已提交/待提交清单并保留快照。

### 遇到的问题

- 多文件系统没有通用的跨文件原子 rename，因此没有把“两文件同时切换”包装成虚假的原子承诺；本轮只建立可靠提交边界并显式暴露部分提交状态。
- 初版注入式暂存函数与 Node `writeFileSync` 重载签名不一致，改为显式分支调用后类型构建通过。
