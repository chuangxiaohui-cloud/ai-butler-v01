# ADR 索引

> 用途：记录“技术选型、分层策略、模块划分原则”等跨模块决策，是推导链的第二环。
> 权威需求：`一人公司AI-Agent需求文档_v2.5.md`；Agent 入口约束：`AGENTS.md`。

## 为什么需要 ADR

- 需求文档回答“做什么”，不回答“为什么这么实现”。
- AGENTS.md 回答“Agent 开发时怎么被约束”，不记录决策过程与备选方案。
- ADR 记录已经落地或即将落地的架构决策，避免后续开发凭记忆重做选型。

## 流程

1. 出现新决策或推翻旧决策时，在 `docs/adrs/` 新建 `NNNN-<slug>.md`。
2. 每个 ADR 必须包含：背景、决策、备选方案、后果、状态。
3. 状态使用 `proposed` / `accepted` / `superseded`；被替代的 ADR 保留原文并标记
   `superseded -> NNNN`。
4. 需求正文仍是唯一规格权威：ADR 与需求冲突时以需求为准，需要时走需求变更流程。
5. 行为或参数变更仍按 AGENTS.md 纪律：先写计划、跑 doc-lint、登记 E-NN 与 bench。
