# UI 交互设计稿

> 权威需求：§4.1 / §9.1-§9.3；实现：`ui/prototype/`

## 1. 三栏 × 三模式

| 栏 | 主角色 | 内容领域 | 默认执行方式 |
|----|--------|---------|-------------|
| 工程开发 | 架构师 + PM + 老板 | EDA/编码/结构/仿真 | Plan / Craft |
| 知识咨询 | 老专家 | 芯片/Datasheet/技术问答/GitHub | Ask / Craft |
| 生活助手 | 贴身女秘书 | 急救/健康/天气/闲聊 | Ask |

Ask / Craft / Plan 是“怎么干”，三栏是“干什么”，两者正交。

## 2. 当前 UI 结构

- L0 侧边栏 / L1 导航：工程开发、知识咨询、生活助手。
- 中间对话区：消息流、附件、模型切换器、Ask/Craft/Plan 模式胶囊。
- 右侧产物栏：文件列表、HTML 预览、变更记录、风险提示。
- 底部终端抽屉：经 gateway `/api/terminal/exec` 执行，Shell 开关默认关闭。
- 设置面板：服务商 / 安全 / 路由校准 / 技能 / 记忆 / Token 用量，已接真实 API。

## 3. 证据链交互

- 证据卡片显示 `[hard]` / `[soft]` 标签、来源域名、分数、URL。
- 点击证据打开来源或本地文件；`file` / `terminal` / `test` / `search` 四类交互见 §9.2。
- 回复下方提供 👍 / 👎 / 修改建议，反馈回写 Experience / Skill 生命周期。

## 4. 串栏与上下文

- 栏位是上下文，不是能力闸门。
- 知识类串栏必应；执行类跨栏需真正切换上下文。
- 输入时按意图实时推荐栏位，不自动跳转；用户手动选择优先。
